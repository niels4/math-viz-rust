# math-viz2-rust idioms

The port copies the semantic intent of math-viz2 (`/opt/dev/agent/src/math-viz2` at the milestone's hash) and writes it as idiomatic Rust. Intent is held by the vitest tests ported one for one (same names, same expected values), the layout boxes measured from the reference, the pixel and behaviour judgment through `tools/run`, and the table in each progress file of every TypeScript export against its Rust item. Shape is held by this mapping, the pedantic clippy set the workspace denies, and the smell list at the end.

## TypeScript to Rust

| TypeScript | Rust | Note |
|---|---|---|
| Discriminated union (`PlotLine`'s `kind: "arrow" \| "dashed" \| "measured"`, `ScrubMode`) | `enum` with payloads, exhaustive `match` | the `kind` tag disappears; a `readonly T[]` payload is `Vec<T>` or `Box<[T]>` |
| String-literal union (`TransformParam = "a" \| "b" \| "h" \| "k"`, `FunctionSlug`, `ThemeSlug`) | fieldless enum; `EnumMap`/`EnumSet` for records and sets keyed by it | `Record<TransformParam, number>` → `EnumMap<TransformParam, f64>` |
| `undefined`, `null`, `?.`, `??` (`flipAtom`'s `null`, `font: string \| null`) | `Option` and its combinators, `let … else` | never a sentinel value |
| `throw` at a boundary (parsing a query value) | `Result<T, E>` with an error enum and `?`; `panic!` only for an invariant | an unparseable query value falls back to the default, as `queryParamAtom` does |
| Prop callbacks (`onChange`, `setCenter`, `onSettle`) | a message enum handled by the owner (one `update`), or a direct `&mut` call up the ownership chain | never `Rc<RefCell<dyn FnMut>>`; closures only where they stay local |
| Hook state (`useState`, jotai atoms, `useRef`) | fields of the owning state struct, one tree rooted at `App` | `atomWithStorage` → a field written through `prefs.rs` |
| `useEffect` with dependencies | an explicit step of the update or frame function, gated on its inputs' change | |
| `requestAnimationFrame` loops (`useCamera`, `usePlotCurves`, `useShownTransform`) | a step function called once per frame from the app's clock with the frame's `dt`, with the same `firstFrameMs` and `maxFrameDt` rules | the harness's paused clock gives the same 16 ms frames on both sides |
| Module-level `let` and singletons (`getDefaultStore()`) | owned by `App`, borrowed down; `thread_local!` only for FFI payload lifetimes, `static Mutex` only for a callback on another thread | |
| Objects with known keys, `Partial<Record<…>>` | structs (with `Option` fields) or `EnumMap<K, Option<V>>`; `HashMap`/`BTreeMap` only for dynamic keys | |
| `number` | `f64` for maths and values, `f32` where NanoVG takes it, `usize`/`i32` for counts and indices; `as` at boundaries only | JS semantics (`%` sign, `Math.round`, `toFixed` ties, `toPrecision`) through `mv-numfmt` where tests pin them |
| Arrays, `.map/.filter/.reduce/.find` | iterators and adapters; `&[T]` parameters, `Vec<T>` only when owned | no index loops |
| `string`, `.length`, `.slice` | `&str` parameters, `String` fields; JS counts UTF-16 units, so every index or length is a named decision with a test | the readout's true minus sign (U+2212) and `−` in labels stay as bytes |
| Classes (none in math-viz2) | struct and `impl` | |
| The file split | modules follow ownership and the domain (plane, camera, grid, readout, scrub), not the component tree; `pub(crate)` by default, `pub` only at a crate's surface | the plan's §1.2 names the module per file |
| vitest tests | `#[test]` one for one, same names and expected values; a component test is ported against the module's state model (what the DOM showed becomes what the state holds) | the intent anchor |

## React, CSS, Canvas and the browser to this app

- **A component** becomes a layout function taking `&mut App` through `ui_scope` (Clay's element scope) and the state it reads; its CSS module becomes layout constants in the function and tokens in `mv-theme` (regenerated by `tools/run themes` from a table of selectors and custom properties). A `data-theme` rule becomes a per-theme token. `@media (hover: hover)` is true natively and in every engine the harness runs.
- **jotai atoms** become `App` fields; a derived atom (`litAtom`) becomes a method; an `atomWithStorage` becomes a field loaded and saved through `prefs.rs`. A write-only atom that records "who moved last" becomes a method that updates a field.
- **The URL** (`queryParamAtom`) is app state: `App.url` holds the query; each `QueryParam<T>` keeps the live value, the debounce, flush, equality and history rules of the TypeScript; the web build mirrors it into the page URL through `library.js`; natively the harness sets it with `--query` and reads it from `views.json`.
- **Canvas 2D** (`drawCartesianPlane.ts`) becomes NanoVG calls through `mv-nvg`: `beginPath/moveTo/lineTo/stroke` map one to one; `setLineDash` to `nvg` dash emulation as the first port did (`$MV_RUST_SRC/crates/mv-plane/src/paint.rs` shows the technique, not the semantics); `fillText` with `textAlign`/`textBaseline` to shaped text through `mv-text` at the same font, size and baseline rule; `devicePixelRatio` scaling to the density the window reports; `globalAlpha` to the colour's alpha; the 1 px line on the half-pixel grid stays on it.
- **Pointer and wheel events** become SDL events decoded in `input.rs` and routed by hit region; `setPointerCapture` becomes the app's capture state; `wheel` deltas keep math-viz2's unit rules (`deltaMode` × 16, the trackpad threshold).
- **`document.fonts.load`** waits are no-ops natively (fonts are always loaded); the state before the font loaded is recorded, not reproduced.
- **`document.startViewTransition`** becomes a cross-fade of the previous frame over the new one through a frame layer, over the measured duration.
- **`prefers-reduced-motion`** is the app's reduced-motion setting (SDL's system query natively, `matchMedia` on the web), read where `canAnimate()` reads it.
- **Screen-reader text** (an `aria-live` region) has no native equivalent and is a recorded known gap.
- **Tests that render** become tests of the state model and the layout function's output (boxes from a headless `App` with `fixture::headless_app()`), never of pixels; what has to draw is judged through the harness.

## Before you return

Read your diff for these and fix what you find: `.clone()` to end a borrow fight; `Rc<RefCell<_>>` in app state; `String` or `Vec` parameters; `Option<bool>` as a tri-state; `unwrap` outside tests; a `kind` field in a struct; stringly-typed state; `Box<dyn Any>`; index loops; a function taking `&mut App` to read one field; `pub` everywhere; an `#[allow]` without a comment naming its reason; a TS idiom transliterated (`as any`, a truthiness check, `===` on floats where the TS compared with a tolerance). `cargo clippy --workspace --all-targets -- -D warnings` is clean on every commit; `-W clippy::pedantic` is a report the reviewer attaches, not a gate.
